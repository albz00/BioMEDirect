BioME Admin Platform

                
A working reference for the video–to–lesson control panel

                

                    
                    
                

                

                    
                    
                

            

            

                

                    
BioME · Internal platform reference · Text & No-Text video pipeline

                    

                        This document describes the BioME admin platform end to end — what it is, how the
                        pieces fit together, and what each control does. It is meant to be read top to bottom
                        the first time, then kept as a reference. If you just want to get going, open the
                        Workflow tab.
                    


                    
1. Overview

                    

                        BioME delivers an interactive biology curriculum where every lesson is a single source
                        video paired with a clickable chapter menu. A student can watch straight through or jump
                        to any chapter; the video freezes on title cards and loops on review segments until they
                        choose to continue. This panel is where that interactive behavior is authored. It turns a
                        plain .mp4 into a structured, navigable lesson without anyone editing source
                        HTML by hand.
                    


                    
2. Architecture

                    
The platform has four layers that all read and write the same per-lesson record:

                    
    
                        
  • Storage — Firebase Storage holds the raw .mp4 source videos. Text videos live in videos/; No-Text videos live in videos/x/.
    • 
                        
  • Database — Firestore stores everything about a lesson: its display name, the assigned video path, the generated timeline, raw detection data, and the green→menu mapping.
    • 
                        
  • Compute — Cloud Functions do the heavy lifting: scanning a video for colour cards, running GPT vision to read title cards, and metadata operations.
    • 
                        
  • Runtime — on the live lesson page, masterUIcontrol.js reads the saved timeline and mapping and drives the freeze / loop / seek behavior during playback.
    • 
                    

                    

                        The admin panel itself (admin.html, admin.js, admin.css)
                        is the editor that sits on top of all four. Nothing you do here touches the original lesson
                        HTML; every change is stored as data and applied at runtime.
                    


                    
3. Core concepts


                    
Lessons and variants

                    

                        Every lesson exists in two parallel variants. Text videos
                        carry on-screen text and use IDs ending in _t; No-Text videos
                        have the text stripped and use IDs ending in _x. They are managed independently:
                        the same lesson can have a finished Text timeline and no No-Text video at all. The
                        Text / No-Text toggle in the sidebar decides which variant every action on
                        the page targets, so set it before you do anything else.
                    


                    
The source video

                    

                        Each lesson points at exactly one video. By default that is videos/<id>.mp4
                        (or videos/x/<id>.mp4 for No-Text), but you can override it by assigning any
                        uploaded video. The override is stored in the lesson's videoPaths field.
                    


                    
The timeline

                    

                        The timeline (stored as srcArray) is the heart of a lesson. It
                        is an ordered list of every card detected in the video, each with a playback start and end.
                        The runtime walks this list to know where chapters begin, where to freeze, and where to loop.
                    


                    
The colour marker model

                    

                        Lessons are authored by dropping full-frame colour cards into the source video. The detector
                        recognises three:
                    

                    
    
                        
  • Yellow — a freeze. Playback pauses on the content after the card until the student clicks.
    • 
                        
  • Green — a freeze and a menu anchor. Like yellow, but a green card also marks the spot a menu chapter can link to. Greens are what the AI mapping reads.
    • 
                        
  • Red — a loop. On reaching a red card, playback returns to the previous freeze marker and replays that segment until the student clicks.
    • 
                    


                    
4. The detection pipeline

                    

                        Generate source decodes the assigned video and scans it for the three colour
                        cards. It runs a dense scan at the video's native frame rate, groups runs of coloured frames
                        into events, and discards any shorter than the minimum card duration (so a single stray frame
                        is not mistaken for a card). The accepted yellow, green and red events are then merged in time
                        order to rebuild the timeline. Each row's playback window is the content after its
                        card; the card frames themselves are not part of playback.
                    

                    

                        Generate source rebuilds the timeline from the video by design, so it replaces the previous
                        one. Wipe timeline clears the detection and timeline data while keeping the
                        assigned video, so you can regenerate from a clean state.
                    


                    
5. AI green→menu mapping

                    

                        Detection knows where the green cards are, but not which chapter each one
                        introduces. Run AI green→menu mapping sends each detected green title card
                        to GPT vision, reads the printed title, and matches it to the closest chapter in the lesson
                        menu. The result fills the green→menu mapping table for you to confirm or override; it
                        never changes the timeline itself.
                    

                    

                        When you Save menu mapping, every chapter with a confirmed green becomes a
                        live link: clicking that chapter on the live page seeks straight to the moment just after its
                        green card. Chapters left as — none — simply start from the beginning.
                    


                    
6. Playback behavior

                    

                        On the live lesson page the runtime loads the saved timeline and mapping and applies them
                        frame-accurately: it freezes on yellow and green markers, loops on red markers back to the
                        previous freeze, and honours saved chapter links so a menu click jumps to the right timestamp.
                        Because all of this is data, edits you save here apply to every student immediately —
                        there is no redeploy step.
                    


                    
7. The interface, control by control


                    
Header

                    
    
                        
  • Instructions — opens this document.
    • 
                        
  • Changelog — the history of changes to the panel.
    • 
                        
  • View Main Menu — opens the live student-facing central menu.
    • 
                        
  • Profile — your signed-in account and a Logout button.
    • 
                        
  • Workflow — the casual getting-started guide (the Workflow tab of this document); the best place to start.
    • 
                    


                    
Action bar

                    
    
                        
  • Scan / Refresh — rebuilds the lesson list from the main menu and reloads Storage videos. Run it first; lessons missing a video sort to the top.
    • 
                        
  • Upload Video — uploads one or more .mp4 files. Files ending _x.mp4 are filed under videos/x/ (No-Text); everything else goes in videos/ (Text). A single file whose name matches a lesson ID is auto-assigned.
    • 
                        
  • Status — progress and result messages appear as a pop-up in the bottom-right so you can keep scrolling while a task runs.
    • 
                    


                    
Sidebar

                    
    
                        
  • Text / No-Text toggle — chooses the variant every action targets. Remembered per device.
    • 
                        
  • Search — filters the lesson tree by name as you type.
    • 
                        
  • Filters — All, Missing (no video), or Has Video.
    • 
                        
  • Status badge — shows whether the current variant has a video attached.
    • 
                        
  • Collapse arrow — hides the sidebar to give the editor more room.
    • 
                    


                    
Lesson & Video card

                    
    
                        
  • Lesson Name — the display name shown in the menu. Editing it never touches source files.
    • 
                        
  • Video dropdown — every Storage video; No-Text entries are prefixed x/.
    • 
                        
  • Assign / Update — links the selected video to the lesson via the videoPaths override.
    • 
                        
  • Use default path Dev — clears the override so the lesson uses its default path; keeps the timeline.
    • 
                        
  • Reset for reattach Dev — detaches the video and wipes timeline/detection data so you can attach a fresh one. Chapter names are kept.
    • 
                    


                    
Timeline editor

                    
    
                        
  • Generate source — runs the three detectors and rebuilds the timeline.
    • 
                        
  • Run AI green→menu mapping — matches each green card to a chapter; fills the mapping table, never changes the timeline.
    • 
                        
  • Save menu mapping — saves the green→menu links so chapters become live seek targets.
    • 
                        
  • Save all — saves the edited timeline rows to Firestore.
    • 
                        
  • Wipe timeline — clears timeline + detection data but keeps the video.
    • 
                    

                    

                        The timeline table lists every detected card in time order. The everyday columns are
                        index, type (the card colour), and the playback
                        start/end. The flag, lock and raw
                        card / debug columns are diagnostic and only show in Dev mode.
                    


                    
Green→menu mapping table

                    

                        Appears after AI mapping. Each row is one green card, showing its start, the seek time just
                        after it, the AI-read title, a dropdown to confirm or override the menu chapter, the AI's
                        confidence and reason, and an optional reviewed checkbox that only records human
                        review and does not affect playback.
                    


                    
Available Videos

                    

                        Expand this card to browse Storage, split into Text (videos/)
                        and No-Text (videos/x/) groups. Preview plays a
                        video in a pop-up without assigning it; Delete Dev
                        permanently removes a video and its timeline and clears any lesson using it.
                    


                    
8. Data & persistence

                    

                        Each lesson is one Firestore record. Key fields: videoPaths (assigned video per
                        variant), srcArray (the timeline), the raw yellowDetection /
                        greenDetection / redDetection blocks, and the saved green→menu
                        mapping. Display-name overrides for lessons and sections are stored alongside. Because state
                        lives in Firestore and Storage rather than in code, content work needs no deploy.
                    


                    
9. Developer mode

                    

                        Dev mode (the toggle at the very bottom of the dashboard) reveals the
                        machinery: raw detection tables for yellow, green and red events, calibration inputs such as
                        minimum card duration, the marker-model context, and the “Export for Cursor”
                        buttons that copy timeline / error / full reports for debugging. It is off by default and
                        should stay off for normal content work — leave it on only while diagnosing detection.
                    


                    
10. Operating notes

                    
    
                        
  • Stay signed in with an admin account so your changes save.
    • 
                        
  • Saved changes apply to every student immediately.
    • 
                        
  • Set the Text / No-Text variant before uploading or assigning, so the video lands in the right place.
    • 
                        
  • If detection looks wrong on one video, turn on Dev mode, check the raw event tables, and adjust the minimum card duration or red thresholds before regenerating.
    • 
                    

                


                

                    
BioME · Getting started · The everyday loop

                    

                        New here? This is the short version — the path most days follow, start to finish. For
                        the why behind any of it, switch to the Documentation tab.
                    


                    
Before you start

                    

                        Make sure you're signed in with an admin account (top-right Profile), and
                        decide whether you're working on the Text or No-Text version
                        of a lesson. Everything below targets whichever variant is selected in the sidebar toggle.
                    


                    
The everyday flow

                    
    
                        
  1. Scan / Refresh. Load every lesson and every video in Storage. Lessons still missing a video float to the top of the list.
    2. 
                        
  2. Pick a variant. Flip the Text / No-Text toggle to the version you're building. It's remembered, but double-check it before uploading.
    3. 
                        
  3. Get a video on the lesson. Either Upload Video (name a No-Text file something_x.mp4 so it files itself correctly), or pick an existing one from the dropdown, then Assign it.
    4. 
                        
  4. Generate source. This scans the video for the yellow, green and red cards and builds the timeline. Watch the status pop-up; it can take a moment.
    5. 
                        
  5. Run AI green→menu mapping. The AI reads each green title card and guesses which chapter it belongs to, filling the mapping table.
    6. 
                        
  6. Check the mapping. Skim the green→menu table. Fix any wrong guesses with the chapter dropdown; set anything that isn't a real chapter to — none —.
    7. 
                        
  7. Save menu mapping, then Save all. The first saves the chapter links; the second saves the timeline rows. Both are needed.
    8. 
                        
  8. See it live. Open View Main Menu, play the lesson, and click a couple of chapters to confirm they jump to the right spots and the freezes/loops feel right.
    9. 
                    


                    
If something looks off

                    
    
                        
  • Chapters jump to the wrong place — re-open the lesson, fix the rows in the green→menu table, and Save menu mapping again.
    • 
                        
  • The timeline looks wrong or empty — Wipe timeline and Generate source again from a clean state.
    • 
                        
  • Detection keeps missing cards — turn on Dev mode (bottom of the dashboard), inspect the raw event tables, tweak the minimum card duration, and regenerate.
    • 
                        
  • Wrong video attached — use Reset for reattach (Dev) to detach and clear, then assign the right one.
    • 
                    


                    

                        That's the whole loop. Once it's familiar it takes only a few minutes per lesson — most
                        of the time is just waiting on Generate source and the AI mapping.
